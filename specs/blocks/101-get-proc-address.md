# Block 101 — `wgpuGetProcAddress`

Status: **IMPLEMENTED (2026-09-22)** — `yawgpu/src/ffi/proc_address.rs`; all 202 header names + vendor exports resolve; `nm` shows `_wgpuGetProcAddress`. Note: the fn-pointer erasure needs one fixed-type `transmute::<*const (), unsafe extern "C" fn()>` (rustc rejects `as` between fn-pointer types of different signatures), so R5 is met with that single helper rather than pure `as` casts. Backlog item **B1** in
`specs/tracking/backlog.md`; closes the last C-ABI gap
(`webgpu-h-export-gap-abi-diff`: 201 of 202 `wgpu*` symbols exported).

## Surface

```c
typedef void (*WGPUProc)(void);
WGPU_EXPORT WGPUProc wgpuGetProcAddress(WGPUStringView procName);
```

Returns the address of the named exported entry point, or `NULL` when
no such entry point exists. bindgen maps `WGPUProc` to
`Option<unsafe extern "C" fn()>`.

## Behaviour contract

- **R1** Every `wgpu*` function declared in the pinned
  `yawgpu/ffi/webgpu-headers/webgpu.h` (202, including
  `wgpuGetProcAddress` itself and the macro-generated
  `*AddRef` / `*Release` / `*SetLabel` exports) resolves to the same
  address the linker exports for that symbol.
- **R2** Every `yawgpu*` vendor entry point exported by the crate
  (`yawgpu/ffi/yawgpu.h`) resolves too; entries behind a cargo feature
  (`tiled`, `shader-passthrough`) resolve only when that feature is
  compiled in, and are `NULL` otherwise.
- **R3** An unknown name, an empty name, and a name that merely prefixes
  or extends a real one (`wgpuCreate`, `wgpuCreateInstanceX`) return
  `NULL`.
- **R4** `procName` follows `WGPUStringView` rules: `length == WGPU_STRLEN`
  means NUL-terminated (use the existing `conv::strings` helper); a
  null `data` with `length == 0` or `WGPU_STRLEN` is the empty name;
  non-UTF-8 bytes return `NULL`. No panic on any input.
- **R5** The lookup table is the single place that enumerates the
  exports. It is a `match` on `&str` (or a sorted static slice with
  binary search) generated by a macro that takes the identifier list,
  so each arm is `stringify!(name) => Some(name as unsafe extern "C" fn())`
  with the fn-pointer cast going through the exact signature (no
  `transmute` of arbitrary types; cast `fn` item → its own fn-pointer
  type → `unsafe extern "C" fn()` via `as`).
- **R6** A unit test parses the pinned `webgpu.h` at test time
  (`concat!(env!("CARGO_MANIFEST_DIR"), "/ffi/webgpu-headers/webgpu.h")`,
  regex-free: lines starting with `WGPU_EXPORT` containing `wgpu…(`)
  and asserts each declared name resolves non-null — so a header bump
  that adds a function fails the test until the table is extended.

## Tests

- `wgpuGetProcAddress_resolves_every_header_declaration` (R1 + R6).
- `wgpuGetProcAddress_returns_the_exported_symbol_address` — for a
  handful of names (`wgpuCreateInstance`, `wgpuDeviceRelease`,
  `wgpuGetProcAddress`) the returned pointer equals the function's
  address.
- `wgpuGetProcAddress_resolves_vendor_exports` (R2) — `yawgpuDeviceCreateExternalTexture`
  always; a `tiled` name under `#[cfg(feature = "tiled")]` and its
  `NULL` under `#[cfg(not(feature = "tiled"))]`.
- `wgpuGetProcAddress_returns_null_for_unknown_prefix_and_extension_names` (R3).
- `wgpuGetProcAddress_handles_string_view_forms` (R4): `WGPU_STRLEN`
  NUL-terminated form, explicit length, empty, null data.
- ABI check: `nm -gU target/debug/libyawgpu.dylib | grep wgpuGetProcAddress`
  shows the export (Claude runs on review).

## Out of scope

- A `WGPUProc`-typed table exposed to C (`WGPUProcTable`); not in the
  pinned header.

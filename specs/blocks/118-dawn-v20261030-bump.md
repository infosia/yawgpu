## Problem

`third_party/dawn` tracked the fork branch `feature/tiled` (upstream
`c8f5ca3df8`, 2026-06-25, plus TBDR commits). The target is the fork's TBDR
commits rebased on upstream tag `v20261030.184100` (`97ae1b10ac`), 1847 commits
later. Most of the API drift is mechanical, except for one contract change:

Upstream `9de0fd6708` ("[tint][msl] Use immediates for buffer size metadata")
removed the MSL writer's uniform path. `ArrayLengthOptions::ubo_binding` and
`Output::needs_storage_buffer_sizes` are gone: storage-buffer sizes are now a
`array<u32, N>` member of the immediate block at
`ArrayLengthOptions::buffer_sizes_offset`. yawgpu's Metal path bound them as a
separate `setBytes` buffer at `buffer_sizes_slot`.

`msl::writer::Options::non_constant_zero_offset` also became a mandatory
internal immediate. Its default of 0 collides with user immediates at offset 0
and fails generation with "overlaps with previous member", so it must be set on
every MSL generation.

## Rules

### Immediate block layout (Metal)

R1. The per-stage MSL immediate block is laid out in Dawn's order, skipping
absent items:

| Item | Offset | Size | Present |
|---|---|---|---|
| user immediates | 0 | `user_immediate_size` (layout budget, not stage usage) | always reserved |
| frag-depth clamp | `user_immediate_size` | 8 | entry uses `frag_depth` |
| non-constant zero | next | 4 | always |
| buffer sizes | next | `4 * N` | `N > 0` |

The layout is computed in one place in the shim. `N` is the count of storage
bindings plus vertex-pulling buffers. There is no vec4 padding: the member is
`array<u32, N>`. The delivered block size is rounded up to 16 bytes, matching
Dawn's `kSetBytesAlignment`, because `setBytes` must cover the MSL struct.

R2. `non_constant_zero_offset` and, when `N > 0`, `buffer_sizes_offset` are set
on every MSL generation. The non-constant-zero word delivered to the shader is
always 0.

R3. Sizes keep their existing index order and values: storage bindings in
`ordered_size_bindings` order, then vertex-pulling buffers at
`num_storage + i`.

R4. A stage whose `N > 0` must receive the block even when it has no user
immediates and no clamp. A stage needing the block when no immediate binding
slot is available fails generation with a clean error, never silently.

R5. `needs_storage_buffer_sizes` is removed through the whole stack (shim
output, Rust FFI struct and its offset guards, core, HAL). "Needs sizes" is
`N > 0`.

R6. The separate Metal buffer-size binding is removed: no `setBytes` at a
buffer-sizes slot in compute, render, render-bundle, or subpass encoding. The
HAL fills the sizes into the composed immediates block. Metal slot allocation
must not change for user bindings or vertex buffers.

R7. All paths compose through one helper. The subpass path, which passes empty
user immediates, must still deliver clamp and sizes.

R7a. No buffer write that can reach the block's slot may follow the block before
a dispatch or draw. The slot chooser only sees resources the entry point
references, while the HAL binds every layout entry. Compute and the render stream
therefore write the block last. The subpass path may write textures, samplers,
and used vertex buffers after it, because those use separate tables or slots the
chooser already reserves, and that path has no external textures.

### Mechanical fixes

R8. `SwizzleResultToScalar` is ported to the current `Builder::Swizzle` return
type with unchanged behaviour.

R9. The shim build provides Dawn's build-config defines through upstream's
mechanism (`dawn_utils_config`). `NDEBUG` is the one explicit define, for
non-Debug configs, because the Rust `cmake` crate drops it on Visual Studio
generators.

### Non-changes

R10. SPIR-V and GLSL generation output contracts do not change: the options the
shim sets still exist, and the options removed upstream were never set by the
shim. R11 is the one exception, and it fixes output rather than changing a
contract.

### Upstream validation tightening

R11. `DepthRawReadTransform` must produce IR that is valid for the retyped
sampled texture, because Tint now validates it. After retyping a depth texture
to its sampled form:
- `textureSampleLevel`: convert the `i32`/`u32` level to `f32`. The level is
  located by overload, since array and offset forms shift its position.
- `textureGather`: prepend component `0`, keeping every other argument.
- Every depth overload of these two builtins that the retype can reach is
  covered, including array, cube, cube-array, and offset forms.

This also corrects the generated GLSL: GLSL ES has no implicit `uint` to `float`
conversion, so a `uint` LOD was never portable.

R12. Tint now rejects invalid `@subgroup_size` override values before core
rule 4 sees them, and yawgpu accepts Tint's messages; Dawn takes the same path.
Non-zero non-power-of-two values fail during substitution (upstream
`d72152d1b9`, "@subgroup_size value must be a power of two"). Zero passes
substitution and fails in the IR validator ("@subgroup_size param must be
greater than 0"). Core rule 4 stays as a backstop with its direct unit test; no
override value reaches it through pipeline creation.

R13. WGSL arrays in `var<immediate>` are rejected (upstream `e5dd1223d8`, citing
the WGSL spec). yawgpu inherits this from Tint. webgpu-native-cts
`pipeline_immediate:required_slots_set` `scenario="dynamic_indexing"` still uses
such a shader and fails until the suite is updated.

the `subgroupShuffle` failures do not reproduce there, so no library fix follows
from them. Run on Windows 11 / RTX 5060 Ti at pin `843d53377`, on a webgpu-native-cts
checkout that predates `2e86bb6`, with SPIR-V robustness enabled, so the

Only the subgroup queries were run on Windows. The whole suite has since passed on
Linux native Vulkan at this pin: see the Linux section of
`specs/blocks/119-cts-d116bcc-findings.md`. The e2e suite under the Khronos layer
passed 140/140. GLES
through WGL passed 38 of 39: `e2e_gles_process_exit` crashes with
`0xC0000005` on every run. F-153's exit guard is armed only on the EGL path, and

This pin also broke `cargo build --release` on Windows. With a Visual Studio

`yawgpu-tint/shim/CMakeLists.txt` defines `NDEBUG` for every non-Debug config.
